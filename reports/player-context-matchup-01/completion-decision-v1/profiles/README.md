# Roster-driven as-of profiles — C v1

The reusable adapter is `src/receiving_profiles_c02.py`. It constructs every QB/RB/WR/TE query from explicit roster and event records; target-game statistical appearance is not a population filter. C supplies receiving proxies, with explicit owner-A rushing and owner-B quarterback unavailable sections rather than fabricated profile values.

Actual first output: **53 profiles** for WAS–NYG (8 QB, 15 RB, 20 WR, 10 TE), source cutoff 2026-11-10T04:54:42.615077Z. All are **UNQUALIFIED_ROSTER_OR_STATUS_VERSION** because the observed roster is Week9 while the future event is Week10. This is a usable preliminary as-of information product, not an operational forecast or paper admission. No injury source was retrieved and no player is declared healthy or starting. The native scheduled event was fresh at the recorded cutoff; status expiry is separate from preserved snapshot time.

Canonical readback is `current-W10/PROFILES.json.gz` plus `PASSER_ROLE_OVERLAY.json.gz`, checked against `PROFILE_METADATA_CORRECTION.json`. The original 53-profile bytes and exact generator source are preserved; the role overlay fixes passer-versus-QB labeling without changing counts/features/scores. The index retains every player and exclusion, including sparse and unavailable records. The real examples and separate zero-target software fixture are described in EXAMPLES.md.

The adapter emits explicitly ordered E0/E2/E3 inputs. New model binding checks source-contract identity, lookback, ordered fields, primitive model hash, fit/availability clocks and target-game exclusion. Legacy v1.1 models cannot inherit this new2024-warm-start/current-source contract. Old output arrays and their zero-context coarsening remain frozen. A non8 profile window needs a matching newly evaluated fit, not columns inserted into an old model. This package performs zero model fits and zero acquisitions.

Executed command: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python src/receiving_profiles_c02.py --snapshot sources/player-context-matchup-01/completion-decision-v1/current-query --cutoff 2026-11-10T04:54:42.615077+00:00 --output reports/player-context-matchup-01/completion-decision-v1/profiles/current-W10`. The current facts combine baseline2022–25 plus freshly observed2026 rows in memory through existing `data_v2.load`; no duplicate full archive is written. Context uses2024/2025/fresh2026 PBP with strict earlier-only prefixing. The separate historical-builder option retains the old reconstruction panel and is not authenticated pregame history.

Validation: ten software fixtures cover missing-target-stat inference, future mutations, strict cutoff boundary, knownzero versus undefined/missing, historical teams, RB trick passers and unknown roles, source/freshness gates, duplicate IDs, started games, typed model binding and exact-line count-law support. These tests add no NFL observations or accuracy claims. The first full-profile build did not log CPU; its actual completion/file clocks are retained instead of rerunning merely for timing. The generation receipt records zero fits/HTTP. Public schema is a C-coordinated envelope proposal; A/B adoption is not assumed.

Live admission additionally requires a fresh matching native scheduled event at the actual execution clock (UTC now by default), observed within30minutes, futurekickoff and profilecutoff no later than admission. Historical profile validation is separate and cannot issue through the live path. Expired, started and identity-mismatched fixtures fail closed; existing53preliminaryprofiles remain blocked and unchanged.
